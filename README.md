# ILS Risk Conformance Suite

A language-neutral **specification** and **test corpus** for insurance-linked
securities risk calculations, with independent implementations in Python, Scala,
Julia and Excel.

[![conformance](https://github.com/OWNER/ils-conformance/actions/workflows/ci.yml/badge.svg)](https://github.com/OWNER/ils-conformance/actions/workflows/ci.yml)
· **[Documentation](https://OWNER.github.io/ils-conformance/)**
· **[Specification](spec/spec.md)**

The specification is the product. The implementations are evidence that it is
implementable; the disagreements between them are the findings.

## Status

One case — expected loss over a 10,000-year loss table — and the numeric
conventions it forces. Layer mechanics, reinstatements, indexation, hours
clauses and EP curves are the roadmap, not the current contents.

## Running it

Requires [`just`](https://github.com/casey/just). Each implementation keeps its
own toolchain; the justfile is the only glue.

```bash
just check          # corpus integrity -- run this first
just test           # every implementation
just test-python    # or one at a time
just scorecard      # regenerate docs/results.md
```

Individually:

```bash
uv run --project impl/python pytest impl/python/tests -q
cd impl/scala && ./mill test          # ./mill is bootstrapped by `just bootstrap-scala`
julia --project=impl/julia -e 'using Pkg; Pkg.instantiate(); Pkg.test()'
uv run --project impl/excel python impl/excel/runner.py   # needs LibreOffice
```

## Design commitments

**Tolerances live in the case data.** No implementation gets to hold its own view
of "close enough", and no implementation is compared against another — every one
is compared against the golden value. Widening a tolerance is a breaking change
to the specification (§ 4.5), not a fix.

**Implementations are idiomatic, and may disagree.** In the context of simulation error, this disagreement should not be material.

**Implementations share the corpus and nothing else.** The Excel harness is
written in Python and is one careless import away from becoming a wrapper around
the reference implementation, at which point agreement between the two columns
would mean nothing. `tools/check_independence.py` enforces this in CI.

**Builds are not unified.** uv, Mill and Pkg each do their own job. Bazel could
subsume all three; the Scala and Julia rulesets would cost more than the problem
is worth.

**Excel is a first-class implementation, not a demo.** It is the highest value impelementation from an educational perspective
